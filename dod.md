# Definition of Done

## For Individual Tasks/Features

A task is considered "Done" when:

- Task is committed to GitHub with a clear message
- Any change has been reviewed by at least one team member
- Feature works as expected (tested locally)
- No breaking changes to existing functionality
- Task status updated in GitHub roject to "Done"

## For Sprint Completion

A sprint is considered "Done" when:

- All committed tasks meet the individual DoD
- Changes are merged to main branch
- Sprint review completed with team
- Any known issues documented in the repository
- Demo-ready for stakeholders (if applicable)

### Testing

 - The feature has been tested locally in WordPress environment.
 - Edge cases and user scenarios have been considered.
 - No existing functionality is broken by the new changes.
 - Forms and user inputs are validated appropriately.

### Security & Compliance
 - User data handling follows privacy best practices.
 - Input validation and sanitization are implemented.
 - BlueHost security configurations are maintained.
 - No sensitive credentials or data are committed to the repository.

## For Project Milestones

A milestone is considered "Done" when:

- All features in scope are complete
- Testing completed on staging environment
- Documentation updated (if needed)
- Client/instructor approval received (if applicable)
- Deployed to production (BlueHost)

---

**Note:** This DoD should be reviewed and updated by the team as needed throughout the project.
